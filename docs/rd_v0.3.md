## 1. 并发模式扩展（修订 rd_v0.2 §4.2）

| 特性 | 说明 |
|------|------|
| 并发模式 | 支持 **SPSC**（单生产者单消费者）、**MPSC**（多生产者单消费者）与 **MPMC**（多生产者多消费者） |
| **模式选择** | **编译期通过 `HPULOGC_CONCURRENCY` 选择（SPSC / MPSC / MPMC），不可运行时更改**（沿用 v0.2 §4.2） |

### 1.1 MPMC 语义（规范性）

- MPMC 构建运行 **N 个对称消费者线程**（N 见 §2），共同消费**同一个**环形缓冲；**每条日志恰好被一个消费者处理一次**（恰好一次语义：不丢失、不重复，受溢出策略约束）。
- 消费者线程对输出层的处理沿用全局配置锁串行执行（与单消费者版本相同的处理路径）；MPMC 并行化的环节是**出队与认领**。每消费者独立输出缓冲（真并行落盘）不在本期范围。
- **顺序保证（相对 v0.2 的变化）**：单消费者构建（SPSC/MPSC）保持既有保证——单生产者严格 FIFO、多生产者下单条记录原子完整；MPMC 构建**不保证记录间的全局输出顺序**（记录被任意消费者认领后并行处理）。单条记录自身仍原子完整（撕裂不可能）。依赖全局顺序的调用方应使用 SPSC/MPSC 构建。

### 1.2 溢出策略可用性（修订 v0.2 §4.3 表格）

| 策略 | 有锁（SPSC/MPSC/MPMC） | 无锁 SPSC | 无锁 MPSC | 无锁 MPMC |
|------|------------------------|-----------|-----------|-----------|
| **discard** | ✅ | ✅ | ✅ | ✅ |
| **overwrite** | ✅（互斥锁下天然安全） | ✅ | ❌（沿用 v0.2：配置即启动失败） | ❌（同 MPSC：配置即启动失败） |
| **wait** | ✅ | ❌ | ❌ | ❌ |

> 实现注记（非规范）：无锁 MPMC 出队采用「commit 字租约认领」（认领成功者独占拷贝后再推进消费游标），物理上无数据竞争，TSan 全程干净；这与无锁 overwrite 的 seqlock 协议（v0.2 时代已存在的固有物理竞争、TSan 跳测）不同。

### 1.3 消费者线程数量（新增 `[async]` 配置键）

| 键 | `consumer threads` |
|----|--------------------|
| 取值范围 | 1 – 16 |
| 默认值 | 1 |
| 生效时机 | **仅 init**；热加载忽略变更并输出 stderr 警告（与 `[buffer]` 同类，v0.2 §10.5） |
| 构建约束 | 值 > 1 需要 MPMC 构建；非 MPMC 构建（含同步构建、异步 SPSC/MPSC 构建）配置 > 1 时**启动失败**返回 `HPULOGC_ERR_CONFIG`（值合法但构建不支持，v0.2 §10.4 规则） |
| 代码内配置 | `hpulogc_config_t` 追加字段 `consumer_threads`（追加式 ABI 规则，v0.2 §10.6；`hpulogc_config_default` 置 1） |

- 默认值 1 保证配置文件跨构建可移植；MPMC 构建配置为 1 合法（退化为 MPSC 行为）。
- 值为 0 或 > 16：任何构建均启动失败（`HPULOGC_ERR_INVALID_ARG`，代码内配置路径）或钳制+警告（配置文件路径，沿用 clamp+warn 惯例）。

## 2. 生命周期语义扩展（修订 v0.2 §7.5）

- **init**：按 `consumer threads` 启动 N 个消费者线程；任一线程创建失败时按已创建集合回滚（请求退出、回收后返回失败），init 失败语义不变（库回到未初始化、可重试）。
- **flush**：等待**所有**消费者确认已提交各自已取出的记录（每消费者独立 ack），且环空；等待上限沿用 `shutdown timeout`（0 = 无限）。
- **shutdown**：置退出标志 → 唤醒全部消费者 → 有界等待全部退出（`shutdown_timeout_ms`）→ join 全部 → 销毁环。退出后各消费者协同清空环内剩余记录（记录被 N 个消费者分配认领）。
- **fork**：子进程内消费者线程不存在（fork 只保留调用线程）；atfork 子进程处理器重置消费者簿记状态，`fork behavior = reinit` 的惰性重建按当前配置重新启动 N 个消费者。

## 3. 构建与可观测性（修订 v0.2 §7.3/§11/§13.5）

- `HPULOGC_CONCURRENCY` 接受 `SPSC | MPSC | MPMC`（默认仍为 MPSC）；非法值 CMake 配置期 `FATAL_ERROR`。
- `hpulogc_build_info_t.concurrency` 取值扩展为 `"spsc" / "mpsc" / "mpmc"`。
- 统计恒等式（v0.2 决策 16）在多消费者下保持成立：`accepted = written + dropped + overwritten + throttled + 在途`；`written` 计数为原子累加，多消费者并发递增安全。
- 测试矩阵扩展：环形缓冲单测按 `{locked, lockfree} × {SPSC, MPSC, MPMC}` 6 组合编译运行；MPMC 端到端集成测试仅在 MPMC 构建注册。

|------|------|
| 非 MPMC 构建 `consumer threads > 1` | 启动失败，返回 `HPULOGC_ERR_CONFIG` |

## 5. 实现注记（非规范性）

- **无锁 MPMC 认领协议**：消费者先以记录头 commit 字做 CAS 租约认领（`pos+1 → pos+2`），认领成功者独占拷贝（拷贝跳过 commit 字本身），拷贝完成后推进消费游标 `deq`。租约持有期间生产者不可能复用该内存（`deq` 未越过），因此无锁 discard 路径全程无物理数据竞争；SPSC/MPSC 保持原单消费者路径（零额外开销）。
- **内存开销**：每消费者持有独立 staging 缓冲（当前按环容量分配），N 消费者的 staging 内存为 `N × buffer size`；缩减为按最大记录分配列为后续优化。
- **预存缺陷实录**（本阶段发现，非 MPMC 引入，见 implementation_notes）：TSan 下 `hpu_core_trigger_reload` 存在两处与热加载路径相关的预存数据竞争（`g_rt.state` 设计为普通 int 的读-mostly 模型、Phase 1 解析阶段无锁读取 `g_rt.conf`），Linux TSan + lockfree 构建可复现，与并发模式无关。
