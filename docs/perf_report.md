基准构建配置：`-O2`（延迟/吞吐）、库与基准同配置；`CLOCK_MONOTONIC` 计时；预热 10,000 条后正式测量；延迟场景给出 P50/P99/P999（逐条采样 200,000 条/生产者）。

## 2. 方法学

1. **延迟（逐条采样）**：生产者对每次 `hpulogc_log()` 前后取 `CLOCK_MONOTONIC`，记录差值；多生产者场景用 `pthread_barrier` 同步起跑；结果排序取分位数。**注意：每次采样本身含 2 次 clock_gettime（实测约 35–40 ns）开销**，计入下述数值。
2. **延迟（摊销）**：单次时钟对包裹 200,000 条日志循环，总时差 / 条数——无逐条采样开销，反映真实平均单条成本。
3. **吞吐**：固定 3 秒持续写入（64B/条），以 `hpulogc_get_stats()` 的 accepted 差值计算；输出目标为 `/dev/null`，消费者批量同步写。
4. **基线内存**：`/proc/self/statm` 常驻页差值 + `mallinfo2()` 堆在用量两种口径；先用 64KB 预触初始化 glibc arena，把分配器自身初始化成本排除在库之外；buffer_size=4KB（最小值）且未触碰（不计入常驻）。
5. **min 体积**：`HPULOGC_BUILD_PRESET=min` + `-Os -ffunction-sections -fdata-sections`，链接最小示例程序 + `-Wl,--gc-sections` + `strip` 后读 `.text` 段（`size -A`）。

## 5. 偏差分析

### 5.1 单条延迟（SPSC 无锁）未达 100 ns

分解（组件微基准，同环境实测）：

| 组件 | 实测 |
|------|------|
| 采样开销（2×clock_gettime，含在逐条数值中） | ~35–40 ns |
| 时间戳捕获（1×CLOCK_REALTIME，管线必需） | ~20 ns |
| %msg 渲染（vsnprintf "%s" 63B） | ~15 ns |
| 环形缓冲入队（lockfree SPSC，含 88B 拷贝） | ~23 ns |
| TLS 缓冲获取 + 级别过滤 + 注册表查找 + 原子计数 + errno 保持 | ~25 ns |
| 其余（函数调用、结构填充、WSL2 vDSO 抖动） | 余量 |

结论：**纯管线成本约 130–170 ns**，其中时间戳捕获与各原子操作合计 ~45 ns 为规范管线（§4.9 要求生产者打时间戳）固有成本；逐条采样的 35–40 ns 计量开销使报告值进一步抬高。100 ns 目标按规范管线逐字实现（含时间戳、errno 保持、原子统计）在用户态 C 中难以达到，需放弃规范要求的某项（如时间戳捕获）或引入批量合并时间戳。

**改进建议**：
1. 报告口径增加 rdtsc 采样（消除 vDSO 开销，预期 P50 再降 ~35 ns）；
2. 时间戳按秒缓存 + 粗粒度时钟混合（每 64 条刷新一次 REALTIME，中间用 MONOTonic 差值插值）；
3. `hpulogc_log` 热路径 `__attribute__((hot))` + PGO；
4. 裸金属环境复测（WSL2 虚拟化引入额外抖动，P999 波动 429–2531 ns 即为佐证）。

### 5.2 MPSC 无锁 P99 ≈ 1.0–1.3 μs（目标 < 1 μs）

P50 = 370 ns 达标区间内，P99 超出 0–32%。来源：8 生产者 CAS 竞争排队 + WSL2 vCPU 调度抖动（P999 达 2.5 μs 显示调度片尾）。裸金属上预期 P99 落入 1 μs 内。改进：生产者本地 staging（批间合并 CAS）、按 NUMA/核绑定的生产者分组。

### 5.3 MPSC 有锁 P99 ≈ 34 μs（目标 < 10 μs）

P50 = 343 ns 良好；P99 尖峰来自：消费者在批量边界持环互斥量拷贝记录 + 每 10ms flush 周期的输出写（/dev/null write + stdio flush 约 2–5 μs）与 8 个生产者的锁竞争叠加；WSL2 调度放大。改进建议：
1. 消费者批量拷出改为"双缓冲槽 + 单次指针交换"，把记录拷贝移出互斥量；
2. flush 与取队解耦（独立 IO 线程或 IO 缓冲独立锁）；
3. 有锁环的 wait 路径加自适应自旋（减少 futex 挂起/唤醒往返）。

### 5.4 min 体积 20,560 B（规范目标 8 KB）

构成：库被引用代码 ~10 KB、CRT/动态链接支撑 ~6 KB、格式化与输出路径 ~4 KB。8 KB 目标按当前功能集（含 sync 模式全管线、格式预编译引擎、文件输出）不可达；已通过注册表惰性链接（g_rt BSS 从 20,896 B 降至 952 B）、`-ffunction-sections/--gc-sections`、`-Os` 收敛到 20.6 KB（用户修订上限 32 KB 内）。

进一步缩减建议：`-ffunction-sections` 覆盖平台 OBJECT 库、`fprintf` 族换自研最小格式化（省 ~2 KB）、裁剪 conf 校验诊断字符串（省 ~1 KB）。

## 6. 内存口径说明

| 口径 | 数值 | 说明 |
|------|------|------|
| mallinfo2 堆在用差值 | **6 KB** | 库自身分配（conf 快照 + 5 个预编译格式 + 输出结构） |
| statm 常驻差值（预触 arena 后） | 328 KB | 含 glibc brk/arena 粒度效应（首次 malloc 触发的 124 KB arena 预分配 + 堆顶预扩展），非库分配 |
| BSS（hpu_runtime_t） | 952 B | 注册表已移出运行时结构（CATEGORY=OFF 构建被链接器裁剪） |

结论：库真实基线 < 32 KB 达标；statm 口径受分配器粒度支配，不作为达标依据，仅作参考并列。
